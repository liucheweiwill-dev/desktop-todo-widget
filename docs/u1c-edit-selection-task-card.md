# U1c — 修正編輯時的選取反白，並把新增輸入框移到底部

> 起因：2026-09-08 人工驗證 C2／C4／C6 通過，但：
> 1. **C5 失敗**：雙擊編輯時藍底蓋住文字，看不到原本寫什麼
> 2. 使用者要求把 `Add a task…` 輸入框**從頂部移到底部**

## 第一部分：修正選取反白（C5）

### 根因

WPF `TextBox` 的選取呈現由三個屬性決定：

| 屬性 | 作用 |
|---|---|
| `SelectionBrush` | 反白的底色 |
| `SelectionOpacity` | 反白底色的不透明度（預設 `0.4`） |
| `SelectionTextBrush` | **選取範圍內文字的顏色** |

目前 `SelectionTextBrush` 未設定（或與底色對比不足），且反白底色不透明，
因此選取範圍內的文字被蓋掉。雙擊進入編輯時通常會全選文字，於是整行都看不見。

### 要求

- **明確設定 `SelectionTextBrush`**，與 `SelectionBrush` 有足夠對比
- `SelectionOpacity` 不得為 `1`；建議 `0.4`–`0.5`，讓底下的文字仍透出來
- **兩個 `TextBox` 都要處理**：頂部（將移到底部）的新增框、以及就地編輯框
- 未選取時的文字、游標（`CaretBrush`）維持 U1b 已通過的狀態，不得回歸

### 順帶確認

雙擊進入編輯時是否全選文字？若是，**保留該行為**（方便整句改寫），
修好反白後全選也讀得到。若不是，也不要改成全選。

## 第二部分：輸入框移到底部

### 要求

`Add a task…` 輸入框從視窗頂部移到**清單下方**，成為最底一列。

- 清單區域佔上方，隨視窗高度伸展；輸入框固定在底部
- **Enter 新增、輸入框清空、焦點保留**的行為完全不變
- 新項目仍加到清單**尾端**（不因輸入框位置改變而改為加到開頭）
- 清單捲動時輸入框**不跟著捲走**，固定在底部

## Risk notes

- **不要用「把選取關掉」來解 C5**——選取是必要功能（要能反白改寫）。
  要解的是可讀性，不是把功能拿掉。
- 移動輸入框時容易不小心改掉「新項目加到尾端」的行為。
  輸入框在底部會讓人直覺想把新項目也加在附近，**但順序必須維持加到尾端**，
  否則 R1 的拖曳排序與使用者既有的手排順序會亂掉。
- 本卡是外觀與版面，**不得更動 `TodoListViewModel` 或任何持久化邏輯**。
